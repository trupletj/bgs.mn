# Ухаалаг хуваарилах — тогтмол автобусны дугаараар давхар хуваарилах

## Зорилго

Shift-exchange (ээлж солилцоо)-ийн "Ухаалаг хуваарилах" (Smart Assign) товч нь одоогоор
зөвхөн чиглэлээр л pool-ыг автобусанд хуваарилдаг тул компанийн зохион байгуулалт
(жишээ нь: "Инфинити Спейс"-ийн хүмүүс байнга #1 автобусанд, "МТЛ"-ийнхэн #2 автобусанд)
харгалзагдахгүй байсан. Ажилчдын ~90% нь ээлж бүрд ижил автобусаа давтдаг тул HR тэднийг
гараар дахин дахин зөөх шаардлагатай болдог байв.

Энэ өөрчлөлт нь хүн бүрийн "тогтмол автобус"-ыг санаж, дараагийн ээлжид анхны
сонголтоор нь оруулж, зөвхөн дүүрсэн тохиолдолд л ердийн best-fit fallback руу шилждэг
болгоно.

## Эцсийн шийдвэрүүд (хэрэглэгчтэй ярилцаж баталгаажуулсан)

1. `public.users.bus_number` (integer, nullable) — тухайн хүний тогтмол автобусны дугаар.
   Нэрээр (`name`) таарал хийхийн оронд тогтвортой identity багана ашиглана — учир нь
   огт хамааралгүй хоёр хүн санамсаргүйгээр ижил ерөнхий нэртэй автобусанд (жишээ нь
   хоёр өөр ХУУЧИН ээлжинд аль аль нь "#2" гэдэг автобусанд) орсон тохиолдолд нэрээр
   таарал хийх нь санамсаргүй "нэгдэх" эрсдэлтэй.
2. `bgs_attendance.buses.bus_number` (integer, nullable) — тухайн автобусны дугаар, ижил
   чиглэл дотор `users.bus_number`-тай харьцуулах зорилготой.
3. Тухайн хүний тогтмол автобус **дүүрсэн бол pool-д үлдээхгүй** — ердийн
   best-fit/шинэ-автобус-үүсгэх fallback руу шууд орж, өөр автобус руу fill хийнэ.
4. `bus_number`-ыг HR гараар бөглөх шаардлагагүй — түүхэн өгөгдлөөс **нэг удаа backfill**
   хийж, цаашид анх удаа автобус авсан хүн бүрийн хувьд **автоматаар бичигдэж**
   (self-bootstrapping) үлдэнэ.
5. Автобус автоматаар үүсгэхэд нэрэнд `#` тэмдэгт ашиглахгүй (жишээ: "Улаанбаатар 1").
6. `actions/shift-exchange.ts`-ийн `autoDistributePool()` action болон
   `components/shift-exchange/smart-assign-button.tsx` UI-д ямар ч код өөрчлөлт
   шаардахгүй — логик бүхэлдээ `bgs_attendance.auto_distribute_pool` RPC (Supabase
   migration) дотор байрлана.

## Хийгдсэн ажил (2026-07-02)

Supabase дээр 2 migration шууд applied:

1. **`add_bus_number_columns`** — `public.users.bus_number` болон
   `bgs_attendance.buses.bus_number` (integer, nullable) баганууд нэмсэн.
2. **`backfill_users_bus_number`** — идэвхтэй хэрэглэгч бүрийн хамгийн сүүлийн (`pa.id desc`)
   өмнөх ээлжийн `bus_id is not null` бичлэгийг олж, холбогдох `buses.name`-с эхний тоог
   (`substring(name from '\d+')::int`) гаргаж авч `users.bus_number`-т бичсэн. ~737/2832
   идэвхтэй хэрэглэгч утгатай болсон (олдоогүй нь NULL хэвээр — шинэ ажилтантай адил
   ердийн best-fit-ээр хуваарилагдана).

`bgs_attendance.auto_distribute_pool` RPC өөрөө **одоогоор өөрчлөгдөөгүй** —
хуучин алгоритмаараа (зөвхөн чиглэлээр best-fit) ажиллаж байна.

## Хийгдэх ажил (дараагийн алхам)

### RPC-г шинэчлэх

`bgs_attendance.auto_distribute_pool(p_exchange_id, p_capacity=45)`-г
`CREATE OR REPLACE FUNCTION`-ээр шинэчилнэ (signature/буцаах утга
`buses_created, assigned, still_pooled` хэвээрээ үлдэнэ). Одоогийн per-direction/per-unit
`while` мөчлөгийн **өмнө** шинэ алхам (0) нэмнэ, одоогийн best-fit/шинэ-автобус-үүсгэх
логик (1/2) **бүрэн хэвээрээ, unit бүрийн fallback** хэвээр үлдэнэ:

**Алхам 0 (шинэ):**

1. Unit-ийн төлөөлөгч гишүүний (companion бүлгийн хамгийн бага
   `passenger_assignments.id`-тэй гишүүн; ганц хүний хувьд тэр өөрөө) `users.bus_number`-ыг
   уншина.
2. Утгатай бол:
   - Энэ ээлж, энэ чиглэлд яг тэр `bus_number`-тэй **идэвхтэй** автобус байгаа бөгөөд unit
     бүхэлдээ багтах сул зай бий бол → шууд тэнд хуваарилна (best-fit алгасна).
   - Байхгүй бол → яг тэр `bus_number`-тэй шинэ автобус үүсгэж (нэр: `dir_name || ' ' ||
     bus_number`, жишээ "Улаанбаатар 1", `#` ашиглахгүй; `buses.bus_number := <утга>`),
     чиглэлд нь `bus_routes`-ээр линкэж хуваарилна.
   - Байгаа боловч дүүрсэн бол → unit-ийг pool-д **үлдээхгүй**, доод (1/2) ердийн
     best-fit/шинэ-автобус fallback руу шууд орно.
3. Утгагүй бол (шинэ ажилтан, эсвэл backfill-ээр тодорхойлогдоогүй) → шууд алхам 1/2
   (одоогийн, өөрчлөгдөөгүй логик) руу орно.

**Генерик шинэ автобус үүсгэх (1/2) fallback-д нэмэлт**: шинээр үүсгэсэн автобуст
`buses.bus_number := v_seq`-г бас бичнэ (өмнө нь энэ багана байхгүй байсан тул бичигдээгүй) —
ингэснээр анх удаа энэ автобус авсан хүмүүс дараагийн ээлжид тогтвортой танигдана.
(Тайлбар: 2026-07-02 өдрийн байдлаар шалгахад одоогийн генерик нэрлэх загвар аль хэдийн
`#`-гүй байсан — `coalesce(r.dir_name,'Чиглэл') || ' ' || v_seq` — тул энэ хэсэгт нэр
өөрчлөх шаардлагагүй, зөвхөн `bus_number` бичих алхам л нэмэгдэнэ.)

**Self-bootstrapping write-back**: unit амжилттай ямар нэгэн автобуст (алхам 0-ээр ч,
эсвэл fallback-ээр ч) хуваарилагдмагц, тухайн unit-ийн **бүх гишүүдийн** хувьд, хэрэв
тэдний `users.bus_number IS NULL` бол шинэ автобусны `bus_number`-ээр нь дүүргэнэ.

### Баталгаажуулах

1. Rollback хийгдэх transaction-д бодит pool өгөгдөл дээр
   `select * from bgs_attendance.auto_distribute_pool(<exchange_id>, 45);` дуудаж:
   - `bus_number`-тэй хүн яг тэр дугаартай автобус руу орсныг баталгаажуулна.
   - Тэр дугаартай автобус дүүрсэн үед тухайн хүн өөр автобус руу fallback хийгдсэнийг
     (pool-д үлдээгүйг) баталгаажуулна.
   - `bus_number`-гүй хүмүүс хуваарилагдсаны дараа тэдний `users.bus_number` write-back
     хийгдсэнийг шалгана.
   - Түүхгүй хүмүүс өмнөх шигээ ердийн best-fit-ээр хуваарилагдсаныг баталгаажуулна.
2. `npx tsc --noEmit` — Next.js тал (action/UI огт өөрчлөгдөөгүй тул sanity check).
3. Боломжтой бол апп дотроос бодит "Ухаалаг хуваарилах" товч дарж (dev/staging орчинд)
   үр дүнг нүдээр харах.
